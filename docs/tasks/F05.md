# F05 — Benchmark de modelos de transcrição (aparelho real)

**Status:** [x] concluído

Rodar a shortlist de modelos OpenRouter com corpus pt-BR, medir latência,
precisão e custo no caminho real (janela F03 + cliente F04), e escolher
modelo padrão + fallback. Sem gastar além do teto definido na UI.

## Escopo

- Contratos de clipe, métricas (latência, WER, custo) e orçamento no `shared`.
- Runner que percorre a **rodada 1** da shortlist, pára ao atingir o teto.
- Corpus pt-BR mínimo (frases originais do FlowVoice; nada copiado).
- UI de diagnóstico: teto em USD, texto de referência, gravar clipe,
  executar benchmark, ver ranking.
- Registrar escolha em `docs/PLAN.md`.

## Fora do escopo desta fase

- Rodada 2 completa (só se a rodada 1 não distinguir).
- Prévia ao vivo provisório/final (F06).
- Modelos de revisão/pontuação (F09).

## Sub-tarefas

- [x] **F05.1 — Contratos, corpus e métricas**
  - `BenchmarkClip` (pcm/janela + texto de referência).
  - `BenchmarkBudget` (teto USD + teto de requisições).
  - `BenchmarkReport` / `ModelScore` (WER, latência, custo, erros).
  - Shortlist rodada 1 em código, alinhada a `docs/PLAN.md`.
  - WER normalizado (tokens, sem dependência extra).
  - **Aceite:** testes desktop cobrem WER, orçamento inválido e shortlist.

- [x] **F05.2 — `BenchmarkRunner`**
  - Para cada modelo da rodada 1, transcrever cada clipe com o cliente F04.
  - Medir latência por requisição; somar `costUsd` quando o provedor expuser.
  - Não iniciar novo modelo/clipe se o teto de USD ou de requests estourou.
  - Falha de um modelo não aborta os demais.
  - Escolher padrão (menor WER, desempate latência) e fallback (mais rápido
    distinto do padrão).
  - Logs só com modelo, duração, WER, latência, custo — nunca chave nem áudio.
  - **Aceite:** testes desktop com `TranscriptionClient` fake cobrem ranking,
    parada por teto e isolamento de falha.

- [x] **F05.3 — Override de modelo no cliente F04**
  - Permitir transcrever uma janela com modelo diferente do `OpenRouterConfig`
    sem recriar o grafo de DI.
  - **Aceite:** teste desktop confirma que o JSON envia o modelo pedido.

- [x] **F05.4 — UI de diagnóstico**
  - Campo de teto USD (padrão `1.00`); texto de referência editável.
  - Usar a última sessão finalizada como clipe.
  - Botão para correr a rodada 1; ranking textual (WER / latência / custo).
  - **Aceite:** `:androidApp:assembleDebug` verde.

- [x] **F05.5 — Validação local e no aparelho real**

  - No Galaxy S26 Ultra, com teto explícito: gravar clipe pt-BR, correr

## Observações técnicas

- Priorizar baseline `openai/whisper-large-v3-turbo`.
- Clipe único reutilizado em todos os modelos (grava uma vez).
- Custo desconhecido conta como `0` na soma do teto mas entra no ranking
  como “n/d”; o teto de requests continua a valer.
