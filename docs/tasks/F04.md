# F04 — Integração OpenRouter (transcrição incremental)

**Status:** [x] concluído (F04.1–F04.7, E2E validado no S26 Ultra)

`POST /api/v1/audio/transcriptions` com janelas de áudio da F03, chave local
cifrada, `language=pt` travado, retry/timeout, revisão por overlap, fallback
batch quando streaming indisponível. Depende de F03.

Inspiração Handy (MIT, somente referência — nada copiado):
`effective_language()` (base-aware, nunca sobrescreve intent),
`apply_custom_words` + `word_correction_threshold=0.18`,
`remove_filler_words`, `normalize_transcription_output`,
`detect_output_language`, ao vivo guloso / final feixe, idle unload Min5 com
`touch_activity()` durante gravação.

Lição `intelligent-keyboard/docs/voz-ptbr-medicao.md`: `initial_prompt`
Whisper tem limite útil de 224 tokens (buffer 1024 tudo-ou-nada);
`GlossaryBudget` escolhe o que cabe por comprimento/raridade.

## Observações técnicas

- `language` sempre explícito `pt` (ou `effectiveLanguage`) — nunca `auto`
  contra modelo sem detecção; isso corta a maior fonte de alucinação.
- `temperature` omitido por padrão (greedy); F05 decide se algum modelo pede
  ajuste. F06 usa este contrato para prévia por revisão.
- Ktor `contentNegotiation/json` já existe; adicionar `ktor-client-logging`
  NÃO (risco de vazar chave) — log próprio com redação.
