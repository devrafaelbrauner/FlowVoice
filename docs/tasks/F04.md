# F04 — Integração OpenRouter (transcrição incremental)

**Status:** [x] concluído

Conectar a sessão de ditado do F03 ao OpenRouter: transcrever cada janela de
áudio via `POST /api/v1/audio/transcriptions`, expondo o texto provisório de
forma incremental. Sem streaming parcial documentado pelo OpenRouter, a
prévia "ao vivo" é construída por **revisão incremental por janela**
(F04/F06).

## Escopo

- Cliente HTTP (Ktor) para `POST /api/v1/audio/transcriptions` do OpenRouter.
- Campo de chave OpenRouter + validação no app.
- Armazenamento local **cifrado** da chave (nunca logada, nunca sincronizada).
- Transcrição incremental: cada janela do `DictationSessionController` vira
  uma requisição; resultados agregados em texto provisório (`StateFlow`).
- Tratamento de erros: timeout, retry com backoff, rate limit (429), falhas
  transientes (5xx) e erro de chave inválida.

## Fora do escopo desta fase

- Benchmark de modelos / escolha do modelo padrão (F05).
- UI de prévio ao vivo com distintivo provisório/final (F06).
- Revisão incremental por IA / pontuação (F07/F09).
- Inserção final do texto no campo ativo (já POC no F02; integração em F12).

## Sub-tarefas

- [x] **F04.1 — Contrato de transcrição no `shared`**
  - Definir no `shared` (commonMain) as abstrações de:
    - `TranscriptionClient` (interface: transcrever uma janela, cancelar);
    - `TranscriptionResult` (texto, modelo, metadados de duração/custo se
      expostos);
    - `TranscriptionError` (classificação: rede, timeout, rate limit,
      chave inválida, resposta inválida);
    - `OpenRouterConfig` (endpoint, modelo, timeout, política de retry).
  - Sem dependência de Android na interface (testável no target `desktop`).
  - **Aceite:** contratos compilam no `shared` e têm testes de unidade no
    target `desktop` cobrindo classificação de erros e configuração.

- [x] **F04.2 — Cliente Ktor `OpenRouterTranscriptionClient`**

    - header `Authorization: Bearer <chave>`;
    - timeout de conexão e leitura configuráveis;

  - **Aceite:** `:shared:desktopTest` verde com server de teste (Ktor Test

- [x] **F04.4 — Transcrição incremental ligada à sessão do F03**

    - fila de transcrição com concurrency controlada (1 por vez, em ordem);
    - `StateFlow<String>` com o texto provisório acumulado;
    - marcador/estado por trecho (transcrevendo / ok / falha) para o F06;
    - cancelamento da sessão cancela a fila e a requisição ativa.
  - **Aceite:** testes no `desktop` com `TranscriptionClient` fake confirmam

- [x] **F04.5 — Retry, timeout e rate limit**
  - Política de retry com backoff exponencial (com jitter) para:
    - falhas de rede, timeout e 5xx;

  - Limitar gasto: teto de requisições por sessão configurável (defesa contra
    loop de janelas).
  - **Aceite:** testes no `desktop` com server de teste cobrem: retry em 500,

## Observações técnicas

- OpenRouter **não documenta streaming parcial** de transcrição: a UX de
  prévia é incremental por janela (riscado em `docs/PLAN.md`, seção Riscos);
  se a latência agregada ficar ruim, o modelo/janela são revisados no F05/F06.
- O modelo usado nesta fase é **provisório** (um da shortlist, ex.:
  `openai/whisper-large-v3-turbo`); a escolha final sai do benchmark do F05.
- Segurança (regra obrigatória do repo): a chave OpenRouter fica **local e
  cifrada**, **nunca** sincronizada nem logada.
- Janelas podem ser transcritas continuamente enquanto a sessão está ativa;
  política de janela/silêncio já está definida no F03 (16 kHz, PCM 16-bit
  mono, janela ~4 s).
